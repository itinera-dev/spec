# Proposals

Accepted proposals, the PRDs of Itinera's features: why each feature exists and what was decided. They are never specific to a language, and once accepted they are history; the current definition of every feature is the behaviour specification under [../spec/](../spec/). One file per proposal, named `NNNN-short-name.md` after the issue the proposal came from. A file here is accepted: it was merged after the evaluation described in [PROCESS.md](../PROCESS.md). New proposal files follow [TEMPLATE.md](TEMPLATE.md).

Accepted in [#97](https://github.com/itinera-dev/spec/pull/97).
- [0098: Input adapters and service providers for rescue steps](0098-rescue-step-adapters-and-providers.md) (tier 1, amends 0003, 0060 and 0095): a rescue step may have its own input adapter and service providers, attached to `<step name>_rescue`, and the listing shows them in a rescue section of its step's entry. Accepted in [#99](https://github.com/itinera-dev/spec/pull/99).
- [0102: Global metadata passed to every reporter](0102-global-metadata.md) (tier 1, amends 0008, 0010, 0011, 0054, 0061, 0063 and 0095): entries of a key and a value, the journey ID first, that the dispatcher passes to every reporter as each is set, by the workflow instance before the journey and by steps, hooks and service providers while it runs. Accepted in [#103](https://github.com/itinera-dev/spec/pull/103).
- [0104: The implementation a service provider made, and its data](0104-service-implementation-on-events.md) (tier 1, amends 0011 and 0095): `service_provided` names the implementation the provider made, the concrete type of the instance as the language reports it, and carries the data the provider supplied with it. Accepted in [#105](https://github.com/itinera-dev/spec/pull/105).
- [0106: The retry budget alone decides retries](0106-retry-budget-alone.md) (tier 1, amends 0003, 0008, 0009, 0010, 0011, 0024, 0040 and 0083): a failure carries no retriable flag; a failure or an abnormal termination is tried again while the step's retry budget lasts, unless a hook returns `FailWorkflow`, and `retry on abnormal termination`, on by default, lets a step's descriptor turn off retries of abnormal terminations. Accepted in [#107](https://github.com/itinera-dev/spec/pull/107).
- [0108: Test support](0108-test-support.md) (tier 1, capability `testing`): a recording reporter and the path it reads, fake providers, scripted runs checked before the journey, and recorders that lend a step, hook or input adapter its handles outside a journey; it does not count towards a tier, and its names are suggested. Accepted in [#110](https://github.com/itinera-dev/spec/pull/110).
- [0111: Suggested application interface (not normative)](0111-suggested-application-interface.md) (no tier): a "Suggested names" section in chapters 2, 4, 5 and 6 suggesting the shapes applications meet, such as `keep default` for a step hook, `supplied` for an input adapter, attempts as a type, requests typed by whether they are required, and readers on the result; nothing an implementation must do. Accepted in [#112](https://github.com/itinera-dev/spec/pull/112).
- [0113: Value conversions are calls into custom code](0113-value-conversions.md) (tier 1, capability `value-conversions`, amends 0054): a value conversion, code the application supplies or customises to turn its objects into values and values into its types, that fails while a value is read means `wrong type`, and while a value is captured means `not a value`; neither carries the error. Accepted in [#PRNUM](https://github.com/itinera-dev/spec/pull/PRNUM).
